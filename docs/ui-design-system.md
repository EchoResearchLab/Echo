# Echo Research 设计系统

Echo 的界面语言服务于一个目标：让复杂研究显得清晰、可信、可复盘。高级感来自比例、排版、留白、层级与一致性，不靠装饰堆叠。

## 唯一事实源

设计令牌只定义在 **`crates/echo-web/styles/01-tokens.css` 的单个 `:root` 块**里。组件样式只允许引用令牌，不得写死颜色、间距、时长、圆角。

样式按层加载（顺序见 `crates/echo-web/index.html`），同一属性只在唯一一层定义：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 令牌 | `01-tokens.css` | 颜色、字体、间距、圆角、层级、动效、布局常量 |
| 基础 | `02-base.css` | 重置、文档默认排版、焦点环、滚动条、reduced-motion |
| 组件 | `03-primitives.css` | 按钮、输入、开关、面板、状态页、表格、通知条目 |
| 外壳 | `04-shell.css` | 顶栏、导航、通知/账户浮层、内容舞台、页头 |
| 页面 | `05-auth` / `06-research` / `07-library` / `08-settings` | 各页布局 |
| 浮层 | `10-dialog.css` | 破坏性操作确认对话框 |
| 响应式 | `09-responsive.css` | 断点重排（最后加载） |

> **禁止再追加"覆盖层"。** 本仓库曾经把 6 轮改版叠成一个 7599 行的 `style.css`，里面有 3 个互相覆盖的 `:root`（青 `#0e7490` / Apple 蓝 `#0066cc` / 墨绿 `#356f67`），实际生效的只有最后一个，前面 4600 行是按已失效的颜色写的。要改样式就改对应那一层，不要在末尾再堆一段。

## 设计原则

1. **证据先于容器**：优先用排版、分隔线和留白组织内容；只有输入、浮层和确有边界的工作区才使用表面。不做嵌套卡片。
2. **单一强调色**：品牌蓝（`--brand`）只表示可操作、选中、聚焦和进度，不承担装饰作用。红/绿/橙是语义色，专职表示涨跌与风险，绝不与强调色混用。
3. **功能性玻璃**：`--glass` 只用于顶栏与浮层等需要前后层级的场景；普通信息卡使用平面纸面。
4. **动效解释状态**：位置、展开、进度和浮层出现可以运动；循环动效只允许极弱的环境光与思考指示，且必须尊重 `prefers-reduced-motion`。
5. **金融信息稳定**：数字使用 `tabular-nums`，表格与估值区避免浮动和夸张缩放；缺数显示 `—` 或"未核到"，绝不用 0 占位。
6. **信息优先级不因加载态改变**：流式作答期间不把证据骨架铺在答案上方；证据摘要条与落地后的折叠面板同一行高，答案位置从第一帧到终态不跳。

## 令牌速查

| 用途 | 令牌 | 值 |
| --- | --- | --- |
| 主文字 / 次级 / 辅助 / 极弱 | `--ink-1` … `--ink-4` | `#1d1d1f` `#424245` `#5d5d63` `#6f6f75` |
| 纸面（升起 / 画布 / 沉降 / 内凹） | `--paper-raised` … `--paper-inset` | `#ffffff` `#f5f5f7` `#ededf0` `#e5e5ea` |
| 品牌交互色 | `--brand` | `#0071e3`（hover `--brand-hover`，active `--brand-active`） |
| 纸面上的品牌文字 | `--brand-ink` | `#0062c4` |
| 描边 | `--line-1` / `-2` / `-3` | 透明度 6% / 11% / 20% |
| 语义 | `--danger` `--warn` `--ok` | `#d70015` `#a85400` `#1d7a33`（各带 `-tint`） |

> 强调色**必须避开绿**：原品牌绿 `#24625a` 与"上涨/通过"的绿几乎同色，在一个看股票的
> 产品里用户分不清"这是个按钮"还是"这项涨了"。地基灰也必须是真中性灰，不带色相。

- 间距：`--sp-1`…`--sp-11`，4px 基准。
- 圆角：`--r-xs` 6 / `--r-sm` 8 / `--r-md` 12 / `--r-lg` 16 / `--r-xl` 22 / `--r-full`。
- 层级：`--e-1`…`--e-3`、浮层 `--e-pop`、品牌按钮 `--e-brand`。
- 字体：正文 `--font-sans`；**衬线 `--font-serif` 只用于品牌大标题与页面主标题**，不用于正文；等宽 `--font-mono` 只用于代码。
- 控件高度：`--ctl-sm` 32 / `--ctl-md` 38 / `--ctl-lg` 46；触控目标不小于 `--tap-min` 44。
- 阅读行宽：长文正文上限 `--read-max` 748px（中文约 42–46 字/行）；页面内容上限 `--content-max` 1080px。

## 动效

| 令牌 | 时长 | 用途 |
| --- | --- | --- |
| `--dur-1` | 120ms | 颜色、透明度等原地状态 |
| `--dur-2` | 180ms | 小位移、指示线、浮层 |
| `--dur-3` | 260ms | 元素进场 |
| `--dur-4` | 420ms | 页面级过渡 |

缓动只用 `--ease-out`（进场）、`--ease-in-out`（状态）、`--ease-emph`（强调进场）。

优先动 `opacity` / `transform`，避免触发布局重排。对话里的三处动效：

- **用户气泡**：`bubbleIn`，8px 上移 + 淡入，`--dur-3`，只播一次（`<For>` 按 turn id 保持节点，流式增量不会重启动画）。
- **思考指示**：`stage-dot` 呼吸 + `thinking-wave` 五格从左到右依次亮起（1.5s，逐格延迟 0.12s），节奏平静、右对齐固定位置，不随阶段文案长度跳动。
- **首段答案未到时**：`thinking-skeleton` 三行 + 从左到右的 `skeletonSweep` 扫光；首个 token 到达即换成真实文本 + 尾部光标（`caretBlink`）。

## 组件交互

### 按钮
- 主按钮纯品牌色填充，不用多色渐变。Hover 上移 1px 并加深；按下 `scale(0.988)`。
- 禁用态改用 `--paper-inset` + `--ink-4`，必须与启用态明显不同（此前禁用态是深灰实心，看起来像可点）。
- 加载态同步 `aria-busy`，文案描述结果（"进入研究台""保存设置"），不用含糊的"确定"。
- 破坏性主按钮是唯一使用 `--danger` 填充的地方，只出现在确认对话框里。

### Tab 与分段控件
- 页面级 Tab 用文字 + 底部指示线，与内容轴左对齐；hover 给半宽灰线，选中为全宽品牌线，同时提供 `aria-current`。
- 容器级分段控件用浅底轨道 + 白色滑块；滑块只做 `left/width` 过渡，不弹跳。登录页的登录/注册切换与资料库切面共用同一套语言。

### 输入
- 高度 `--ctl-lg`，中性描边，不用彩色描边。Focus 为品牌描边 + 3px 光环。
- 校验规则在提交前可见；错误信息 `role="alert"`，切换模式时清理过期错误。
- 编辑器（研究提问）随内容长高，上限 208px 后内部滚动；`Enter` 发送、`Shift+Enter` 换行；提交后高度收回一行。

### 图标
- 全部来自 `crates/echo-web/src/icons.rs` 的 20×20 线性图标集，描边取 `currentColor`，尺寸由 CSS 决定。
- **组件内的嵌套结构用直接子代选择器**（`.panel > summary` 而非 `.panel summary`）。后代选择器会捕获面板里任何嵌套的同名元素——估值的逐法明细就曾被证据面板的 `summary` 规则套上 `space-between`，箭头甩到最左、标题甩到最右。
- 不用字符当图标（`×` `⋮` `★` `↑` 会随系统字体漂移）。**破坏性操作必须用垃圾桶图标**，不得用"更多"语义的 `⋮`。
- 装饰性图标 `aria-hidden`，语义由外层控件的 `aria-label` 承担。

### 破坏性操作
- 统一走 `crates/echo-web/src/dialog.rs` 的应用内确认对话框（context 注入 + 单一宿主），不用浏览器原生 `window.confirm`。
- 对话框必须说明后果范围（例如"已创建的监控规则不会自动删除"），确认按钮文案描述动作。
- 支持 Escape 与点击遮罩关闭。

### 估值区间

- **刻度轴的范围是 `min(熊, 现价) … max(牛, 现价)`，不是固定的熊–牛**，估值带只是轴上的一段。现价落在带外恰恰是最该看清的情形（= 这股票贵/便宜）；固定成熊–牛只能让现价标记溢出到卡片外，夹到端点又会让"贵一点点"和"贵一倍"长得一模一样。
- 三档数字与逐法明细都用 `tabular-nums`。相对现价按方向着色：负（贵）用 `--danger-ink`，正（便宜）用 `--ok`——只标方向，不替用户下判断。
- **逐法明细必须可展开**：方法之间的分歧本身就是重要信息，被平均成一个数就看不见了。关键假设跟在明细后面，让每个数字都能追到它的前提。
- 窄屏三档转竖排时隐藏刻度轴——横轴与竖排数字不再一一对应，留着会误导位置关系，空间信息由文字承担。
- 位置百分比也用 `Decimal` 计算，不因为"只是展示"就退回浮点。

### 表面
- 普通卡片：白色纸面、`--line-1` 细边框、`--e-1`，hover 最多上移 2px。
- 浮层允许单层背景模糊，不嵌套玻璃卡片。
- 不使用成排彩色胶囊、装饰性高光边、重复渐变，也不给面板标题挂装饰竖条。

## 展示层格式化

服务端口径与用户可读文本的转换只在 `crates/echo-web/src/format.rs`：

- **时间**一律按浏览器本地时区渲染（`7月24日 14:55`）。服务端存 UTC，把 UTC 数字当本地时间显示会把港股盘后写成盘中——这是事实错误，不是排版瑕疵。
- **原始枚举**（`route.depth` 的 `brief/standard/deep`）与**内部指标名**（`grossMargin`）必须映射成中文；未收录的原样透出，好过显示一个错的中文名。

## 响应式与可访问性

- 断点：1180（收窄栅格）、900（登录并单栏、数据表转卡片）、760（顶栏收紧、研究历史转覆盖式抽屉）。
- **不隐藏功能，只重排**。此前空态用 `display:none` 藏掉了研究对象选择与"深度报告"入口，等于让两个能力在首屏不可达。
- 窄屏默认收起研究历史侧栏，用户落地看到的是研究台本身。
- 登录页在窄屏把表单排在品牌叙事之前；页面必须可滚动——注册模式多两个字段，不可滚动会让邀请码和提交按钮物理不可达。
- 所有操作支持键盘；焦点环不可移除。触控目标不小于 44px。
- 状态不能只依赖颜色；数字、来源、时间在快速扫读时必须清楚。
- 深色模式尚未支持（`html[data-theme]` 目前只有 light）。令牌结构已按可切换设计，加深色只需新增一个 `:root[data-theme="dark"]` 覆盖块，不要在组件层写深色分支。

## 新增界面检查清单

- 能否用排版和留白解决，而不是新增卡片？
- 是否只使用了令牌，没有新的魔法数字？
- Default / Hover / Focus / Active / Disabled / Loading / Empty / Error 是否齐全？
- 键盘、触控、窄屏、reduced-motion 是否可用？
- 加载态与终态之间有没有布局跳动？
- 界面上每个数字是否都有真实来源？**不要为了页面好看编造"12 条证据 · 3 个论点"这类占位数字。**
- **控件的标签与它实际做的事是否一致？**卡片写"开始研究"就必须真的开始研究——曾经它只是把问题填进输入框，用户还得再点一次发送。
- 后端新增的字段是否真的渲染了？估值的 `method_detail` 与 `key_assumptions` 在契约里躺了很久没人画，最该兑现"每个判断都有证据"的地方反而是空的。
